## Goal

The sync sees every card of the Project, not only the first hundred.

## Context

**Evidence:** `tools/project-sync/src/adapters/github/project/mod.rs:52-60` · **Base commit:** `b41c0de`

The loop reads `hasNextPage` but passes the first cursor again, so the second request returns the first page and the loop stops on the duplicate.

**Reproduction:** run the behaviour tests with `tests/fixtures/items_next_page.json` as the second reply; the plan lists only the items of the first page.

## Scope

**Fix:** pass `endCursor` of the last reply to the next request.
**Acceptance criteria:**
- [ ] With two recorded pages the snapshot has the items of both (`cargo test -p caixa-project-sync pages`).

P-01: both change the same reader, and the parser fix lands first.
